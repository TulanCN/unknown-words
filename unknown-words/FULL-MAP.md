# 全图模式

unknown-words 的全图分支:分档规则与三件套格式在 [`SKILL.md`](SKILL.md)(已在上下文),本文件只装全图独有的流程。

checklist(可复制进回复逐项勾):

- [ ] 定目的与档位(§1):Q1 默认题、Q2 条件题,能推断就亮推断顺默认
- [ ] 分组铺词出草稿(§2),再校验词表(§3):本地佐证 → 联网 ≤8 次,差异留痕,高频补出处
- [ ] 成图落盘(§4):三件套按目的调权重,md 头部四要素,渲染 HTML 落当前工作目录,stderr 独立词占比超 1/3 回 §2 补边
- [ ] 交付(§5):说三件事,头部日期即保质期

## 1. 定目的与档位

领域从用户的话里取;太宽就细化到他要动手的那一层(写前端 → 他项目的技术栈那套,而非整个 Web 平台)。

然后确立**目的**与**背景档位**。问决策不问事实:能推断就亮出推断让用户顺默认("我推断你是 X,因为……不对就回个字母"),拿不准才发问;至多一轮、至多两题,每题带推荐答案。

- **Q1 目的(默认题)**:读代码 / 发命令 / 面试汇报 / 带人,四选一。目的决定产出形态,最值得问;能强推断(如"接手项目改 bug"→ 读代码)就只亮推断不发问。
- **Q2 档位(条件题)**:先靠行为证据定档("我是后端,最近在写 Go 服务"→ 后端档;自评仅辅助,系统性偏乐观)。证据不足才发问:拿 2-3 个领域级代表词(K8s 取 pod/helm,前端取虚拟 DOM/组件)问熟悉层级——A 都没听说 / B 听说但说不清 / C 能大致解释 / D 用过且能解释。回答含糊或跨界("C 和 B 之间吧")才追问一句"你之前在哪些场景碰过它?",至多这一问,不进第二轮。
- 两题都需发就同轮;"后端写前端"这类典型触发行为证据充分,多数运行 ≤1 问。

档位决定**对照物**与**跳过项**,按回答分流:

| 回答 | 档位 | 词表起点 | 对照物 | 跳过项 |
|---|---|---|---|---|
| A/B | 新手 | 三件套全给,总览加一段"这个领域在解决什么" | 生活比喻为主 | 无 |
| C | 半跨行 | 高频三件套,中频两行 | 原背景等价物("state ≈ 组件自己的实例字段") | 原领域已覆盖的通用概念(后端出身不铺"API") |
| D 或回答带行为证据 | 同行换岗 | 砍人话定义行,直给行话与黑话 | 同行黑话对照 | 整组跳过(DBA 转 SRE 不铺"索引") |

目的与档位确立后(推断确立也算)写进 md 草稿头部;下一轮交互开头先列"已确立:目的 X / 档位 Y",用户纠错即回落重定档,已答不重问。

## 2. 先分组,再铺词

把领域的词分成几**组**,文档开头先给每组一句总览(读者先拿到地图的形状),再逐组铺词。怎么分组看领域性质——判断标准:读者发命令、读回复时,词从哪个角度出来,就按那个角度归一组。起点参考:

- UI/交互类(前端、移动端):交互模式 / 组件与状态 / 数据流 / 样式布局 / 工具链 / 工程黑话
- 数据类(DBA、数仓):对象类型 / 操作动词 / 一致性与事务 / 运维黑话
- 基础设施类(运维、K8s、云):资源对象 / 生命周期动词 / 网络 / 故障排查黑话

草稿完成的判据:高/中/低三层各占有词,每组有一句总览。铺词同时逐词自问"学它之前先懂哪个词?"——答得出就写 `前置:`;平行词之间不连,但能挂真实上游锚点的都要挂(组件族词挂 `前置: 组件` 这类),树状图靠它长出渐进感。

## 3. 校验词表:先本地,再联网

草稿出齐后校验。检索喂思考,不替代思考:改动只限增删词与补出处,永不阻塞出图。

1. **本地佐证(有项目先做)**:以用户当前 cwd 为准——是 git 仓库或含依赖清单(package.json、go.mod、requirements.txt、pom.xml 等)才算"有项目",否则跳过不猜。只读清单类与入口类文件(依赖清单、import 聚合、CI 配置、README/CONTEXT.md),不全文扫源码,读取 ≤10 个文件,超出按顶层目录分层抽样。项目里实际出现的词,正是"读者未来几周真实会碰到"的最佳证据。
2. **版图新鲜度**(1-2 次检索):领域主流词/工具格局有没有变。搜索词用压缩后的关键词组合而非整句(如 `frontend framework trends 2026 vite adoption`)。
3. **高频词通行性抽检**(每词 ≤1 次,共 ≤5 次):高频层词查现行一手文档,确认还通行、没被替代或换名。
4. **捞新词**:检索撞到而草稿没有的词,补进低频层。

预算与降级:总检索 ≤8 次;无网或检索工具不可用 → 词表照出,头部标注"先验版本,未经联网校验",交付时说明。选源三重启发式:独立性(多个独立来源相互印证才写入)、一手性(官方文档/spec/源码优于教程转述)、新鲜度(有明确日期的近期信息优先)。每处差异落三种记录之一——补词 / 改名 / 标"无差异";高频词出处查不到的标"先验未证",不臆造。

## 4. 落盘

写成 markdown——**它是事实源**,文件头写领域、听众背景、**目的**、日期;产物落**当前工作目录**:用户在哪工作,地图就交付到哪,`<domain>.md` 与渲染出的 `<domain>.html` 同名并排。然后用本 skill 自带的渲染脚本 `scripts/render_editorial.py` 产出 HTML 供人查阅(默认树状图):

    python3 scripts/render_editorial.py <primer>.md -o <primer>.html [--layout TREE|SPREAD|INLINE|HOVER|REVIEW]

- **TREE(默认)**:树状渐进关系图——写了 `前置:` 标注的词按依赖分层、SVG 连线(箭头=学习方向);键盘 ↑↓←→ 级联钻取(↑↓ 同层兄弟内切换,→ 进子节点,← 退一层,空格标记,C 复制追问,Esc 回全图),鼠标悬停预览/点击跳转;无前置的词进底部按族折叠带(列表式低频词留在带里属正常);渲染时 stderr 报独立词占比(`###` 词块口径),超 1/3 告警——回 §2 给游离词补上游后重渲染。按 <kbd>Q</kbd> 直接进全屏 Quiz 出题评分:三件套自动出选择题,答完出分 + 错题回顾,答错过的词下一轮优先再现(评级存 localStorage);出题按前置拓扑序分层取样。前置标注语法见 [`SKILL.md`](SKILL.md) 三件套节,建议给有学习顺序的组补上(树状图据此成图);纯平行概念组不写。
- SPREAD / INLINE / HOVER / REVIEW:瑞士编辑风词表(双栏跨页/行内展开/悬停脚注/复习卡流),不依赖前置标注,任何地图可渲染。

HTML 永远是生成物:地图生长只改 md、重跑脚本。md 落地、头部四要素齐、HTML 渲染成功、高频词出处行齐,这一步才算完。

## 5. 交付时说三件事

1. 撞到地图上没有的词,当场问,问完补进来——地图随使用生长。
2. 发命令前扫一眼对应的那组:用词越准,agent 返工越少。
3. 想深挖,指着那个词追问。

头部日期即保质期:领域迭代快(前端/云尤甚),超半年回来重跑 §3 校验版图。
